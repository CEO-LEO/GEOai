## 4. ถ้อยคำที่ซื่อตรงแต่ยังน่าสนใจสำหรับกรรมการ

หลักคิด: กรรมการทุนอยากเห็น **ปัญหาจริง + สิ่งที่สร้างแล้วใช้ได้ + แผนพิสูจน์ที่เข้มงวด + ทีมที่ซื่อตรงกับข้อมูล** — การยอมรับว่า "ยังไม่วัดความแม่นยำ แต่มีกลไกวัดที่ใช้งานแล้ว" มักน่าเชื่อถือกว่าตัวเลข 87% ที่ถามต่อไม่ได้

**ประโยคเปิดนวัตกรรม (แทนย่อหน้าสรุปเดิม):**
> IAMROOT AI เป็นระบบภูมิสารสนเทศบน LINE ที่ใช้ภาพดาวเทียมเรดาร์ Sentinel-1 (มองผ่านเมฆได้) ร่วมกับ Sentinel-2 และแบบจำลองภูมิประเทศ เพื่อชี้ **จุดในสวนทุเรียนที่ชื้นหรือมีน้ำรวมตัวมากกว่าส่วนอื่นของแปลง** ก่อนที่ต้นจะแสดงอาการ แล้วแปลงเป็นข้อความภาษาไทยที่เกษตรกรอ่านเข้าใจ โครงการนี้ต่อยอดจากต้นแบบที่ใช้งานจริงแล้ว (ผู้ใช้ทดลอง 15 ราย 23 แปลง ต.ค. 2569) และออกแบบกลไก **ยืนยันภาคสนามกับเกษตรกรอาสาและเจ้าหน้าที่เกษตร** เพื่อวัดความแม่นยำของระบบอย่างเปิดเผย พร้อมช่วงความเชื่อมั่นทางสถิติ

**จุดเด่นที่พูดได้เต็มปาก (มีหลักฐานในระบบ):**
- วาดขอบเขตแปลงในแอป LINE (ไม่ต้องติดตั้งแอป) + ตรวจคุณภาพขอบเขตและเตือนเมื่อมีบ้าน/ถนนปน
- แผนที่สีเทียบกันเองในแปลง พร้อมประโยคสรุปและคำอธิบายสี (ไม่ใช้ศัพท์เทคนิค)
- คำแนะนำมาจากตารางที่เจ้าหน้าที่เกษตรตรวจและอนุมัติ (ไม่ใช่ AI แต่งสด) — มีหน้าจัดการและประวัติแก้ไข
- เตือนฝนหนักพร้อมระบุจุดเสี่ยงของแปลง ไม่เตือนซ้ำ
- PDPA: หน้ายินยอม สิทธิ์ดู/ดาวน์โหลด/ขอลบข้อมูล บันทึกการเข้าถึง (ผ่านการออกแบบจริงใน Phase 2)
- ระบบยืนยันภาคสนามในแอป + รายงานเทียบกับผลระบบ (หน้า admin) พร้อมช่วงความเชื่อมั่น — **ตัวกลไกพิสูจน์เองเป็นผลงานที่ส่งมอบได้**
- ชุดทดสอบอัตโนมัติกว่า 400 รายการ · ซื่อตรงต่อข้อมูล: ซ่อนค่าที่ยังไม่ผ่านการตรวจ (ปุ๋ย/ผลผลิต/ระดับเสี่ยง) ไว้จนกว่าผู้เชี่ยวชาญตรวจ

## 5. แผนพิสูจน์ความแม่นยำ (ใส่ในข้อเสนอทุนได้)

> **สถานะการสร้างระบบ:** ส่วนที่ระบุว่า "มีแล้ว" ทำงานบน production ตั้งแต่ 5 พ.ย. 2569 (รอ merge ของ branch `feat/v2-durian-focus` — ดูสรุปในแชท) · ส่วน "ต้องเพิ่ม" ยังไม่ได้สร้าง

### 5.1 คำถามวิจัย
1. เมื่อระบบชี้ว่าจุดใดชื้นกว่าส่วนอื่น/มีน้ำรวม จุดนั้นมีน้ำขังหรือดินแฉะจริงกี่ส่วน (**precision**)
2. จุดที่มีน้ำขังจริงแต่ระบบไม่ได้ชี้มีมากแค่ไหน (**recall / อัตราพลาด**)
3. ต้นทุเรียนในจุดที่ระบบชี้ มีอาการผิดปกติ (ใบเหลือง ใบร่วง โคนเน่า) มากกว่าจุดอื่นหรือไม่ (ความสัมพันธ์ระหว่างผลของระบบกับอาการจริง)
4. ระบบเตือน/ชี้ได้ก่อนพบอาการกี่วัน (**lead time**) — *ต้องเพิ่ม*: ปุ่ม "แจ้งปัญหาที่พบ" พร้อมวันที่ เพื่อจับคู่กับวันที่ระบบเตือน

### 5.2 ผู้เข้าร่วมและความยินยอม
- เกษตรกรอาสา (เป้า 15–25 ราย / 20–30 แปลงทุเรียนในราชบุรี และ/หรือ จันทบุรี) + เจ้าหน้าที่เกษตรเป็นผู้ตรวจอ้างอิง (gold standard) สำหรับบางส่วนของจุด
- **มีแล้ว:** หน้าขอความยินยอมในแอป ข้อ "เข้าร่วมทดสอบระบบเป็นเกษตรกรอาสา" (ไม่บังคับ ค่าเริ่มต้นปิด ถอนได้ทุกเมื่อ) บันทึกประวัติทุกครั้ง · นโยบายความเป็นส่วนตัวฉบับ 5 พ.ย. 2569 ระบุการใช้คำตอบเพื่อวัดความแม่นยำและรายงานผู้ให้ทุนแบบไม่ระบุตัวบุคคล · ⚠️ ควรให้ผู้รู้ PDPA ตรวจถ้อยคำก่อนเริ่มเก็บข้อมูลจริง

### 5.3 การเก็บข้อมูลในแอป (มีแล้ว)
- จุดที่ระบบชี้ว่าชื้น/น้ำรวม: "ไปดูที่จุดนี้แล้ว เป็นแบบนี้จริงไหม? **จริง / ไม่จริง / ไม่แน่ใจ**" + แนบรูปจุดนั้น (บีบอัด ลบ EXIF ฝั่งเซิร์ฟเวอร์ เก็บพิกัด/เวลาแยก)
- **จุดที่ระบบไม่ชี้** (อาสาแตะที่ใดก็ได้บนแผนที่): "ตรงจุดนี้มีน้ำขังหรือดินแฉะไหม?" → ใช้ประมาณ recall
- **ต้นไม้ตรงจุดนี้มีอาการผิดปกติไหม?** ทุกจุด (ทั้งที่ชี้และไม่ชี้) → เปรียบเทียบอัตราอาการระหว่างสองกลุ่ม
- ทุกคำตอบเก็บ "สิ่งที่ระบบแสดงตอนนั้น" (ค่าเทียบในแปลง สถานะ โหมด สวนยกร่อง ฯลฯ) ไว้เทียบย้อนหลังได้
- ทำงานได้เมื่อสัญญาณอ่อนสำหรับรูป (คิวอัปโหลดในเครื่อง)

### 5.4 โปรโตคอลสุ่มจุด (ต้องเพิ่ม/ต้องกำหนดวิธี)
recall ใช้ได้เมื่อ **จุดที่ระบบไม่ชี้ถูกสุ่มมาตรวจ** ไม่ใช่เลือกเฉพาะจุดที่เห็นว่ามีปัญหา — แอปตอนนี้ให้อาสาแตะจุดเอง ซึ่งเอนเอียงได้
ข้อเสนอ: (ก) ให้เจ้าหน้าที่/ทีมวิจัยกำหนดจุดสุ่มต่อแปลง (เช่น 5 จุดไม่ชี้ + ทุกจุดที่ชี้) แล้วส่งให้อาสา หรือ (ข) เพิ่มปุ่ม "ให้ระบบสุ่มจุดมาให้ตรวจ" ในแอป (งานพัฒนา ~1–2 วัน) · หากยังไม่ทำ ให้รายงาน precision เท่านั้น และระบุว่า recall เป็นข้อจำกัด (หน้า admin มีหมายเหตุอัตโนมัติ)

### 5.5 ขนาดตัวอย่างและตัวชี้วัด
- สูตรช่วงความเชื่อมั่นของสัดส่วน: n ≈ z²·p(1−p)/e² (z = 1.96) → ประมาณ precision ให้คลาดเคลื่อน ±10 จุดเปอร์เซ็นต์ ต้องมีคำตอบ "จริง/ไม่จริง" ≈ **100 จุด** (p = 0.5), ±15 จุดต้อง ≈ 45 จุด — ไม่นับ "ไม่แน่ใจ"
- recall ต้องมีจุดที่มีน้ำขังจริงอย่างน้อย ~30 จุด (ขึ้นกับความชุกของน้ำขัง — ช่วงฝนจึงสำคัญ)
- ตัวชี้วัด: precision, recall, อัตราเตือนผิด (1 − precision), อัตราอาการต้นไม้ในกลุ่มที่ชี้ vs ไม่ชี้ (พร้อม **ช่วงความเชื่อมั่น Wilson 95%**), lead time (เมื่อมีข้อมูล) · แยกคำตอบเจ้าหน้าที่ออกจากอาสา
- **กฎการรายงาน (บังคับในระบบ):** แสดงเป็นเปอร์เซ็นต์เฉพาะเมื่อมีคำตอบชัด ≥ 10 · แสดง n และช่วงความเชื่อมั่นเสมอ · เรียกว่า "ตรงกับในแปลง x ใน n ครั้ง" เมื่อตัวอย่างน้อย · ห้ามอ้างเป็นความแม่นยำของระบบทั้งประเทศ
- **เกณฑ์ความสำเร็จ:** ตั้งร่วมกับเกษตรจังหวัด **ก่อนเก็บข้อมูล** (เช่น เขียนว่า "precision ขอบล่างของช่วงความเชื่อมั่น ≥ X%") — ตัวเลข X เป็นข้อเสนอที่ต้องตกลงกัน ไม่ใช่ผลที่ได้ ฉันไม่กำหนดแทน

### 5.6 ระยะเวลา
อย่างน้อย **3–6 เดือน** ให้ครอบคลุมหน้าฝนและหน้าแล้ง · ตรวจภายใน 3 วันหลังที่ระบบสแกน (เรดาร์ใช้ภาพ 12 วันล่าสุด ยิ่งช้ายิ่งเทียบไม่ได้) · ทบทวนสถานะรายเดือน

### 5.7 วิธีวิเคราะห์ผลและการควบคุมความเอนเอียง
- หน้า admin `/dashboard/validation.html`: precision/recall + ช่วงความเชื่อมั่น + ตารางผสมผล (confusion) + อาการต้นไม้เทียบสองกลุ่ม · ส่งออก CSV พร้อมพิกัด (ผู้ดูแลเท่านั้น ไม่มี LINE userId) เพื่อวิเคราะห์เพิ่มด้วยเครื่องมือภายนอก
- ความเอนเอียงที่รู้และวิธีจัดการ: (1) คำตอบเกษตรกรเป็นการรับรู้ → ให้เจ้าหน้าที่ตรวจซ้ำสุ่ม ≥ 20% ของจุดและรายงานความสอดคล้อง (2) อาสาเลือกจุดเอง → โปรโตคอลสุ่ม (ข้อ 5.4) (3) ผู้ตอบรู้ผลระบบก่อนตอบ (ไม่ blind) → รอบเจ้าหน้าที่ตรวจแบบ blind ตามแผน [field-validation-plan](field-validation-plan.md) (4) ฤดูกาลเดียวอาจไม่ครอบคลุม → รายงานแยกหน้าฝน/แล้ง
- เปรียบเทียบฐาน (baseline): ผลของระบบ vs การเลือกจุดแบบสุ่ม (ถ้าระบบไม่ดีกว่าสุ่ม แสดงว่าไม่มีคุณค่า — รายงานตามจริง)

### 5.8 ผลงานส่งมอบจากแผนนี้ (สำหรับตารางผลผลิตของโครงการ)
1. ชุดข้อมูลยืนยันภาคสนามไม่ระบุตัวตน (จุดที่ชี้/ไม่ชี้ + รูปมีพิกัด + อาการต้นไม้)
2. รายงานความแม่นยำพร้อม n และช่วงความเชื่อมั่น แยกฤดู/บทบาทผู้ตอบ
3. ตารางคำแนะนำฉบับตรวจแล้วโดยเจ้าหน้าที่เกษตร (ผ่านหน้า admin)
4. สคริปต์วิเคราะห์ที่รันซ้ำได้ (หน้า admin + CSV)
5. (ถ้าได้ข้อมูลพอ) ปรับเกณฑ์ชี้จุดให้แม่นขึ้นจากข้อมูลจริง — เป็นผลวิจัย ไม่ใช่ข้อกล่าวอ้างล่วงหน้า

## 6. สิ่งที่คุณต้องตัดสินใจ/ทำเอง
1. **แก้เลขสิทธิบัตร 2 รายการ** (หรือถอดออก) และตรวจรายการอ้างอิงที่ฉันยังตรวจไม่ได้ (ข้อ C2–C4, A3–A4)
2. ตัดสินใจว่าจะ **เขียนต้นทุน 186,303 บาท/ไร่ ใหม่** ตามความหมายจริง (ค่าเสียโอกาส) หรือเปลี่ยนไปอ้างตัวเลขความเสียหายจากแหล่งที่ระบุ "ความสูญเสียจากน้ำท่วม/รากเน่า" โดยตรง
3. เลือกว่าจะ **ตัด/แทน** ตัวเลข 87%, 7.3 วัน, <8%, 85%, 150,000 บาท ตามตารางข้อ 4 (ฉันแนะนำให้ตัดทั้งหมด)
4. ยืนยันว่าเพิ่ม **โปรโตคอลสุ่มจุด** (ข้อ 5.4) ในงานพัฒนาของทุน — ฉันทำปุ่มสุ่มจุดได้ถ้าสั่ง
5. ให้ผู้รู้ PDPA ตรวจถ้อยคำความยินยอมก่อนเริ่มเก็บข้อมูลอาสา
6. ตกลงเกณฑ์ความสำเร็จ (ข้อ 5.5) กับเกษตรจังหวัดก่อนเก็บข้อมูล
