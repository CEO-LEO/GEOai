# แผนตรวจภาคสนามช่วงรันคู่ — ตัวเลขความแม่นจริงตัวแรกของระบบ

วันที่: 2026-10-17 (อัปเดต 2026-10-25 หลัง Phase 1c–1g) · ใช้คู่กับการรันคู่ (shadow) วิธีวัดความเสี่ยงใหม่ ([risk-level-review.md](risk-level-review.md))
· วิธีใช้แอปสำหรับเจ้าหน้าที่: [officer-guide.md](officer-guide.md)
รายการแปลงพร้อมพิกัดอยู่ในโฟลเดอร์ `fieldwork/` บนเครื่อง (ไม่ขึ้น git เพราะมีพิกัดและชื่อแปลง)

## 1. หลักการ

- **ตรวจแบบไม่บอกผลระบบ (blind):** ไฟล์ที่ส่งเจ้าหน้าที่มีแค่รหัสแปลง ชื่อ พิกัด — ไม่มีผลของระบบ
  ผลของระบบอยู่ในไฟล์ `*_KEY_do_not_send.csv` ที่เจ้าของโปรเจกต์เก็บไว้เทียบทีหลัง กันการเห็นผลแล้วตัดสินตาม
- ตรวจทั้งแปลงที่ระบบ **เตือน** และ **ไม่เตือน** — ต้องมีทั้งสองแบบถึงจะวัดได้ทั้ง "เตือนถูกแค่ไหน" และ "พลาดแค่ไหน"
- ตรวจภายใน **3 วัน** หลังวันที่ดึงรายการ (สถานะใช้ภาพเรดาร์ 12 วันล่าสุด ยิ่งช้ายิ่งเทียบไม่ได้) และบันทึกวันเวลาตรวจ
- ถามเกษตรกรเรื่อง **ประวัติน้ำขังประจำปี** ทุกแปลง → ใช้ตรวจตัวชี้วัด "ปัญหาประจำแปลง" ด้วย

## 2. แปลงตัวอย่าง

ตอนนี้มีแปลงในระบบที่อยู่ในราชบุรีเพียง **6 แปลง** (สถานะวิธีใหม่ ณ 15 ต.ค.: ชื้นกว่าปกติมาก 1, ชื้นกว่าปกติ 2, ปกติ 3)
ต้องการ 10–15 แปลง จึงขอให้เจ้าหน้าที่ **เพิ่มแปลงที่รู้จักสภาพดีอีก 6–9 แปลง** ผ่านแอป (วาดขอบเขตให้ตรงสวน) โดยคละ:

| กลุ่ม | จำนวนที่แนะนำ | เหตุผล |
|---|---|---|
| สวนที่น้ำขังเกือบทุกปี (เกษตรกรยืนยัน) | 3 | ตรวจตัวชี้วัดปัญหาประจำแปลง และดูว่าวิธีใหม่ "มองไม่เห็น" หรือไม่ |
| สวนที่ระบายน้ำดี ไม่เคยขัง | 3 | ตรวจการเตือนผิด |
| สวนยกร่อง (มีร่องน้ำ) | ≥ 3 (ทับกับสองกลุ่มบนได้) | ราชบุรีมีสวนยกร่องมาก — ข้อมูลภาพของสวนแบบนี้ปนน้ำในร่อง |
| แปลงที่วาดขอบเขตชัด ไม่รวมบ้าน/ถนน | ทุกแปลง | ขอบเขตที่มีบ้านปนทำให้ค่าเรดาร์เพี้ยน (พบในข้อมูลจริง) |

แปลงใหม่มีผลเทียบได้ทันที เพราะใช้ภาพเรดาร์ย้อนหลังที่มีอยู่แล้ว 3 ปี ไม่ต้องรอสะสม
ก่อนลงพื้นที่ ผมจะดึงรายการใหม่ (รวมแปลงที่เพิ่ม) พร้อมสถานะ ณ วันนั้น

**ตรวจเฉพาะแปลงที่ (เพิ่ม 2026-10-17):**
- เจ้าของแปลง **ยินยอมแล้ว** (โทรหรือทักถามก่อนส่งพิกัดให้เจ้าหน้าที่และก่อนเข้าแปลง) หรือ
- เจ้าหน้าที่ **เพิ่มเอง** และรู้จักเจ้าของ/สภาพแปลงอยู่แล้ว
แปลงที่ยังไม่ได้ความยินยอมให้ตัดออกจากรายการที่ส่งเจ้าหน้าที่

### 2.1 วาดขอบเขต 6 แปลงเดิมในราชบุรีใหม่

ตรวจด้วยภาพจำแนกพื้นที่ล่าสุดพบว่าขอบเขตของบางแปลงไม่ตรงสวน (รายละเอียด [boundary-quality-warnings.md](boundary-quality-warnings.md)):

| รหัส | ปัญหา | ให้เจ้าหน้าที่ทำ |
|---|---|---|
| RB-01 | ขอบเขตมีบ้าน/ถนน ~23% | วาดใหม่เฉพาะส่วนที่เป็นสวน |
| RB-02 | ปกติ | ไม่ต้องแก้ (ยืนยันว่าตรงสวน) |
| RB-03 | ปักจุดเดียว จุดอยู่บนบ้าน | วาดขอบเขตสวนจริง |
| RB-04 | ภาพเห็นเป็นพืชไร่/ผัก 69% | ถามชนิดพืช — ถ้าเป็นผัก/พืชไร่จริงขอบเขตอาจถูกแล้ว ถ้าเป็นสวนให้ตรวจขอบเขต |
| RB-05 | ภาพเห็นเป็นพืชไร่/ผัก 86% | เหมือน RB-04 |
| RB-06 | ขอบเขต 0.01 ไร่ (จิ้มซ้อนกัน) | วาดขอบเขตสวนจริง |

**อัปเดต 2026-10-25:** แก้ขอบเขตแปลงเดิมในแอปได้แล้ว — เปิดแปลง → "✏️ แก้ไข" → "วาดขอบเขตใหม่" (ประวัติการตรวจยังอยู่กับแปลงเดิม)
และเลือก **ชนิดพืช + ประเภทสวน** ในหน้าเดียวกัน · ถ้าเคยวาดซ้ำเป็นแปลงใหม่ไว้แล้ว ใช้ "รวมประวัติจากแปลงที่ซ้ำกัน" ในหน้าแก้ไข
· ตอนบันทึก แอปจะเตือนถ้าขอบเขตมีบ้าน/ถนนปนหรือเล็กมาก (กด "บันทึกตามนี้" ได้) · ไฟล์รายการแปลงมีคอลัมน์ `boundary_action` บอกสิ่งที่ต้องแก้

## 4. วิธีสรุปผล (ทำให้หลังได้แบบฟอร์มคืน)

- ตาราง: สถานะวิธีใหม่ (แห้งกว่าปกติ(มาก) / ปกติ / ชื้นกว่าปกติ / ชื้นกว่าปกติมาก — "แห้งกว่าปกติ" เพิ่มใน 1d) × สิ่งที่เจ้าหน้าที่พบ
- ตัวเลขที่รายงานได้: เมื่อระบบบอก "ชื้นกว่าปกติ" ขึ้นไป ตรงกับภาคสนามกี่ใน n · เมื่อระบบบอก "ปกติ" มีปัญหาจริงกี่ใน n
  · วิธีเดิมตรงกี่ใน n (เทียบให้เห็นว่าดีขึ้นจริงหรือไม่)
- **รายงานพร้อมขนาดตัวอย่างเสมอ** เช่น "ตรง 7 ใน 9 แปลงที่ระบบเตือน (ราชบุรี ต.ค. 2569, n=9)" — 10–15 แปลงยังเป็นตัวเลขเบื้องต้น
  ไม่ใช่ความแม่นยำของระบบทั้งประเทศ ต้องเขียนเงื่อนไขกำกับทุกครั้งที่ใช้ใน B2G
- ปัญหาประจำแปลง: เกษตรกรตอบ "เกือบทุกปี" กับ HAND ≤ 2 ม. / ชื้นกว่าสวนรอบข้าง ตรงกันกี่แปลง

## 5. ข้อมูลส่วนบุคคล

- ไฟล์ใน `fieldwork/` มีพิกัดและชื่อแปลงของเกษตรกร — ส่งเฉพาะเจ้าหน้าที่ที่ลงตรวจ ไม่โพสต์ในกลุ่มสาธารณะ
- **ยังไม่มีหน้าขอความยินยอม (PDPA, Phase 2)** — ตรวจเฉพาะแปลงที่เจ้าของยินยอมแล้ว หรือแปลงที่เจ้าหน้าที่เพิ่มเอง (หัวข้อ 2)
  และบันทึกวิธีที่ได้ความยินยอมไว้ในแบบฟอร์ม
