## 3. ผลตรวจ log การเรียก /admin/

- Render เก็บ log ได้ราว 7 วัน → ตรวจได้ช่วง **18–25 ต.ค. 2569** เท่านั้น
- การเรียก `/admin/*` ที่สำเร็จทั้งหมด = GitHub Actions (ตรงกับเวลารัน workflow ทุกครั้ง) + การทดสอบของ Claude จากเครื่องเจ้าของ
- **ไม่พบการเข้าถึงจากแหล่งที่ไม่รู้จัก** ในช่วงที่มี log
- ช่วง **28 มิ.ย. – 17 ต.ค. ตรวจไม่ได้** (log หมดอายุ) — ไม่มีหลักฐานว่ามีการเข้าถึง แต่ยืนยันไม่ได้ว่าไม่มี
- ร่างประเมินเหตุ + ร่างข้อความแจ้งผู้ใช้อยู่ที่ `docs/v2/incident-report.md` **ในเครื่องเท่านั้น** (ไม่ได้ commit เพราะ repo
  เป็น public และไม่ได้ส่งให้ใคร) — การตัดสินใจเรื่องแจ้ง สคส. ตาม PDPA เป็นของเจ้าของ

## 5. ทดสอบบนมือถือ (เปิดแอปจากเมนูในแชท LINE)

1. **เพิ่มแปลงใหม่:** วาดขอบเขต → กดตรวจ → หน้า "ข้อมูลแปลงใหม่" เลือกพืช 2 ชนิด + ลักษณะสวน → แผนที่ขึ้นพร้อมประโยคสรุปเหนือแถบสี
2. **คำเตือนขอบเขต:** วาดคลุมบ้าน/ถนน → มีหน้าต่าง "ลองดูขอบเขตอีกนิดก่อนบันทึก" · ปุ่ม "บันทึกตามนี้" ใช้ได้ · อ่านแล้วไม่รู้สึกว่าถูกตำหนิ
3. **แตะจุดสีบนแผนที่:** มีแผ่นข้อมูล ปัญหา + เหตุผล + วิธีดูแล + ป้าย "ร่าง — รอเจ้าหน้าที่เกษตรตรวจ"
4. **แก้แปลงเดิม:** "✏️ แก้ไข" → เปลี่ยนพืช/ลักษณะสวน → บันทึก · "วาดขอบเขตใหม่" → เห็นเส้นจางของขอบเขตเดิม → บันทึก → "📊 ประวัติ" ยังมีครบ
5. **สวนยกร่อง:** ตั้งแปลงหนึ่งเป็นสวนยกร่อง แล้วกด "🔍 ตรวจ" → ไม่มีลูกศร/วงม่วง และมีข้อความข้อจำกัด
6. **คำแนะนำ:** ปุ่ม "💡 คำแนะนำ" บนการ์ด → มีภาพรวมแปลง (เช่น "ชื้นกว่าปกติ"/"แห้งกว่าปกติ") หรือ "ยังไม่พบเรื่องที่ต้องทำ"
7. **รายงาน:** "📤 แชร์ / PDF" → รอ ~30 วินาที → "เปิดรายงาน PDF" เปิดได้ ภาษาไทยอ่านได้ ไม่มีพิกัด
8. **ไม่มีตัวเลขที่ยังไม่ตรวจ:** หน้าผลไม่มีปุ๋ย กก./ต้น, ผลผลิต กก./ไร่, ค่า NDVI/BSI · ปุ่มเดิม (ตรวจ, ประวัติ, จุดชื้นสะสม, ลบ) ยังใช้ได้

## 6. งานที่ต้องให้คนทำ

1. **ลบ `RENDER_API_KEY` ตัวนี้ทิ้งแล้วสร้างใหม่** ใน Render Dashboard → Account Settings → API Keys
   (key นี้เคยถูกพิมพ์ในแชท) แล้วใส่ค่าใหม่ใน `backend/.env` ถ้ายังต้องให้ Claude ใช้
2. **ลบไฟล์ `backend/.env.bak-*`** (`backend/.env.bak-2026-10-23` เก็บ ADMIN_API_KEY ตัวเก่าที่หลุด) — ไม่ได้ commit แต่ไม่ควรเก็บไว้
3. ถ้ารหัสผ่านฐานข้อมูลใน `SUPABASE_DB_URL` เคยถูกวางในแชทหรือที่อื่น ให้เปลี่ยนรหัสผ่าน DB ใน Supabase ด้วย
4. **เปิด shareTargetPicker** ใน LINE Developers → LIFF app → ตั้งค่า (ปุ่มแชร์ในแอปจะขึ้นเอง ไม่ต้อง deploy ใหม่)
5. ส่ง [recommendations-for-review.xlsx](recommendations-for-review.xlsx) ให้สำนักงานเกษตรจังหวัดราชบุรีตรวจ →
   แก้/อนุมัติที่ `/dashboard/recommendations.html` (กรอกชื่อผู้ตรวจ)
6. ภาคสนาม: ขอความยินยอมเจ้าของแปลง (คอลัมน์ `owner_consent` ใน `fieldwork/`) · ให้เจ้าหน้าที่เพิ่มแปลงที่รู้สภาพอีก 6–9 แปลง
   · ให้ Claude ดึงรายการใหม่ไม่เกิน 3 วันก่อนลงตรวจ · ตรวจตาม [field-validation-plan.md](field-validation-plan.md)
7. ตัดสินใจเรื่องแจ้งเหตุ key หลุดตาม PDPA (ดู `docs/v2/incident-report.md` ในเครื่อง)
8. แก้ไฟล์นำเสนอ (pptx/docx/อินโฟกราฟิก) ตาม [claims-replacement.md](claims-replacement.md) ก่อนใช้กับ B2G
9. ผู้เชี่ยวชาญกรอกค่าทางการเกษตรใน `backend/config/crops.json` (ความอ่อนไหวน้ำขังของแต่ละพืช)
10. LINE OA โควตาหมดถึง 1 พ.ย. — ตัดสินใจเรื่องขึ้นแพลน (มีค่าใช้จ่าย Claude ไม่ทำเอง)
11. หลังได้ผลภาคสนาม: ตัดสินใจเปิดใช้ระดับความเสี่ยงวิธีใหม่และคำเตือน (`RISK_DISPLAY_MODE`, `RISK_ALERTS_ENABLED`)
