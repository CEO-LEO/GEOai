# ทบทวนระดับความเสี่ยง — ทำไม 82% เป็น "เสี่ยงสูง" และข้อเสนอแก้ (รออนุมัติ)

วันที่: 2026-10-16 · ข้อมูล: ผลวิเคราะห์ใน Supabase 16 ก.ย.–15 ต.ค. 2569 (767 แถว, 24 แปลง)
+ ต้นแบบคำนวณจาก Sentinel-1 ย้อนหลัง 3 ปีของ 23 แปลงจริง (สคริปต์อ่านอย่างเดียว ไม่ได้แก้โค้ดระบบ)
แปลงในตารางใช้รหัส P01… แทนชื่อ/พิกัด

---

## สรุปสั้น

1. **ไม่ได้เกิดจากการเทียบกันเองในแปลง** — ระดับความเสี่ยงรวมคำนวณจากค่าเฉลี่ยทั้งแปลงกับเกณฑ์ตายตัว
   (การเทียบกันเองในแปลงใช้แค่ระบายสีจุดบนแผนที่)
2. **สาเหตุหลักคือสูตรความชื้น (SWAB)** ซึ่งแปลงค่าเรดาร์ (VV) เป็น "% น้ำในดิน" ด้วยสูตรที่ตั้งขึ้นเอง
   สมมติว่าเป็นดินเปล่า แต่สวนผลไม้มีทรงพุ่มที่สะท้อนเรดาร์แรงกว่าดินเปล่า → **ทุกแปลงถูกอ่านเป็น "ชื้นเกิน/น้ำขัง" ตลอด**
   (30 วันที่ผ่านมา: ไม่มีผลไหนเป็น "สมดุลดี" หรือ "แห้ง" เลยแม้แต่ครั้งเดียว)
3. **ค่าที่ใช้เป็นค่าเฉลี่ย 365 วัน** → ผลแต่ละแปลงแทบไม่เปลี่ยนจากวันต่อวัน แปลงไหนเป็น "สูง" ก็เป็นสูงทุกวัน
   (19 จาก 24 แปลงเป็น "สูง" ครบทั้ง 30 วัน) — ต่อให้ปรับเกณฑ์ ก็ยังได้คำเตือนที่ไม่บอกอะไรใหม่
4. **ข้อเสนอ:** แยก "ลักษณะแปลง" (ไม่ค่อยเปลี่ยน) ออกจาก "สถานะตอนนี้" และวัดสถานะตอนนี้ด้วย
   **"ชื้นกว่าปกติของแปลงนี้เองในช่วงเดียวกันของปี"** — ต้นแบบลดวัน "สูง" จาก **82% → 6%**
   และคำเตือนจาก **589 ครั้ง → 4 ครั้ง** ใน 30 วัน (23 แปลง)

## 1. เป็นเพราะเทียบกันเองในแปลงหรือไม่ → ไม่ใช่

- `compute_risk_level()` ([rule_engine.py](../../backend/rule_engine.py)) รับค่าเฉลี่ยของทั้งแปลงจาก `analyze_durian_plot()` แล้วเทียบกับเกณฑ์ตายตัว
- การเทียบกันเองในแปลง (`_plot_relative_normalizer`) ใช้แค่ **สีของจุดบนแผนที่** และป้ายจุดเสริมใน "จุดที่พบปัญหา" ไม่มีผลกับระดับรวม
- แต่ข้อสังเกตเรื่อง "ทุกแปลงจะมีจุดแย่สุดเสมอ" ถูกต้องสำหรับ **รายการจุดที่พบปัญหา** — `select_problem_points()` หยิบจุดเปียกสุด/แห้งสุดมาแสดงเสมอแม้ทั้งแปลงปกติ
  → เสนอให้แก้ใน 1d พร้อมระบบคำแนะนำ (แสดงเฉพาะจุดที่ผิดปกติจริงเทียบกับค่าปกติ)

## 4. ข้อเสนอ (รออนุมัติก่อนแก้)

### 4.1 แยก 2 เรื่องออกจากกัน
| | ลักษณะแปลง (แสดงในหน้าแปลง ไม่ส่งเตือน) | สถานะตอนนี้ (ใช้แจ้งเตือน) |
|---|---|---|
| อะไร | ที่ต่ำกว่ารอบข้าง, พื้นผิวเปลี่ยนรายปี, ใบลดลงปีต่อปี | ความชื้นช่วง 12 วันล่าสุดเทียบกับปกติของแปลงเอง |
| เปลี่ยนบ่อยแค่ไหน | แทบไม่เปลี่ยน | เปลี่ยนตามฝน/การจัดการน้ำ |
| ระดับสูงสุด | "ควรสังเกต" (ปานกลาง) | ปกติ / ชื้นกว่าปกติ / ชื้นกว่าปกติมาก |

### 4.2 วิธีวัด "สถานะตอนนี้"
- ภาพเรดาร์ Sentinel-1 (ทะลุเมฆ) วงโคจรเดียวกันทุกครั้ง ค่าเฉลี่ยในขอบเขตแปลง
- **ปัจจุบัน** = เฉลี่ยภาพใน 12 วันล่าสุด · **ปกติของแปลง** = ภาพช่วง ±30 วันของวันเดียวกันในปีก่อน ๆ (สูงสุด 3 ปี ต้องมี ≥ 6 ภาพ)
- z = (ปัจจุบัน − ค่าเฉลี่ยปกติ) ÷ ส่วนเบี่ยงเบนมาตรฐาน → **z ≥ 1 = ชื้นกว่าปกติ (ปานกลาง), z ≥ 2 = ชื้นกว่าปกติมาก (สูง)**
  (เกณฑ์ 1 และ 2 เป็นค่าทางสถิติ ไม่ใช่ค่าทางการเกษตร — ขออนุมัติใช้เป็นค่าเริ่มต้น แล้วปรับตามผลยืนยันภาคสนาม)
- ข้อมูลปกติไม่พอ → แสดง "ยังมีข้อมูลไม่พอเทียบ" ไม่ทาย
- **ผลดีกับสวนยกร่อง:** ร่องน้ำมีอยู่ทั้งในค่าปกติและค่าปัจจุบัน จึงหักล้างกันเอง ไม่ถูกนับเป็นน้ำขังทุกวันเหมือนสูตรเดิม
- แจ้งเตือนเฉพาะเมื่อ **ขึ้นเป็น "สูง"** (ตรงกับระบบที่ทำใน 1b แล้ว)
- ระดับความอ่อนไหวของพืช (`waterlogging_sensitivity` ใน 1c) ใช้ปรับว่าพืชไหนเตือนตั้งแต่ "ชื้นกว่าปกติ" — ค่าต้องให้ผู้เชี่ยวชาญกำหนด

### 4.3 เลิกแสดง "% น้ำ / % อากาศในดิน"
ตัวเลขนี้มาจากสูตรที่ไม่ได้สอบเทียบ ดูแม่นเกินจริง (ขัดกติกาข้อ 2.4) → เปลี่ยนเป็นข้อความระดับ "ปกติ / ชื้นกว่าปกติ / ชื้นกว่าปกติมาก" ทำพร้อม 1c (feature flag ปุ๋ย/ผลผลิต)

## 6. ข้อจำกัดที่ต้องบอกตรง ๆ

- "ชื้นกว่าปกติ" **ไม่เท่ากับ** "น้ำขังที่โคนต้น" — เป็นสัญญาณให้ไปดู ต้องยืนยันด้วยการตรวจภาคสนาม (Phase 2: ปุ่ม จริง/ไม่จริง/ไม่แน่ใจ)
- แปลงใหม่ที่ไม่มีภาพย้อนหลังพอ หรือเพิ่งเปลี่ยนการใช้ที่ดิน จะเทียบไม่ได้หรือผิดเพี้ยน
- เรดาร์ยังได้รับผลจากทรงพุ่ม/การตัดแต่งกิ่ง — ใบเปลี่ยนมากอาจถูกอ่านเป็นความชื้นเปลี่ยน
- ต้นแบบนี้ทดลองกับ 23 แปลงเท่านั้น และยังไม่มีข้อมูลจริงจากแปลงมาเทียบว่าถูกกี่ครั้ง

## 7. ถ้าอนุมัติ — สิ่งที่จะทำ (ประมาณ 3–4 วัน, ทำใน 1c ก่อนคำแนะนำ 1d)

1. ฟังก์ชันใหม่ใน `gee_analysis.py` คำนวณ "สถานะตอนนี้" (ไม่ลบ SWAB เดิม เก็บไว้ใน full_data เพื่อเทียบ)
2. `compute_risk_level()` ใช้สถานะตอนนี้เป็นตัวตัดสินระดับสูง ส่วนลักษณะแปลงสูงสุดแค่ปานกลาง
3. UI/การ์ด: เปลี่ยนคำเป็น "ชื้นกว่าปกติของแปลงนี้" + อธิบายว่าเทียบกับอะไร, ซ่อน % น้ำ/อากาศ
4. เก็บทั้งค่าเดิมและค่าใหม่คู่กัน 2–4 สัปดาห์ (shadow mode) ให้เจ้าหน้าที่เทียบกับภาคสนามก่อนเปิดใช้เต็ม
5. test + รายงานผลก่อน/หลังจากข้อมูลจริงอีกรอบ

**ไม่มีการเปลี่ยน schema** (ค่าใหม่เก็บใน `full_data` JSONB ที่มีอยู่)

| ภาพในค่าปกติ (ต.ค.) | 18–28 ภาพต่อแปลง จาก 3 ปี | พอสำหรับคำนวณ (ขั้นต่ำ 2 ปี ปีละ 2 ภาพ) |
| S1C เทียบ S1A ช่วงบินคู่ | ค่ากลางต่างกัน +0.04 dB แต่รายแปลง −1.5 ถึง +2.0 dB | ไม่มีความเอนเชิงระบบ ส่วนต่างรายแปลงมาจากมุมมองต่างวงโคจร → ใช้วงโคจรเดียวต่อแปลง |

### 8.2 ตัวชี้วัด "ปัญหาประจำแปลง" (แสดงในแอปได้ ไม่ส่งเตือน)

วิธีใหม่เทียบกับปกติของแปลงเอง จึงมองไม่เห็นแปลงที่ชื้น/น้ำขังทุกปี — เพิ่ม "ลักษณะประจำแปลง" แยกต่างหาก:

| ตัวชี้วัด | ที่มา | ป้ายที่จะแสดง | ผลกับ 23 แปลง |
|---|---|---|---|
| ที่ลุ่มต่ำ | HAND (ความสูงเหนือทางน้ำใกล้สุด) MERIT Hydro 90 ม. | ≤ 2 ม. "อยู่ในที่ลุ่มต่ำมาก" · ≤ 5 ม. "อยู่ในที่ลุ่มต่ำ" | 11 แปลง ≤ 2 ม., 16 แปลง ≤ 5 ม. (จาก 22) |
| ชื้นกว่าสวนรอบข้างเป็นประจำ | ค่าเรดาร์หน้าฝน 2567–2568 เทียบพิกเซลต้นไม้รัศมี 3 กม. | percentile ≥ 90 → "ชื้นกว่าสวนรอบข้างส่วนใหญ่ในหน้าฝน" | คำนวณได้เฉพาะแปลงที่เป็นต้นไม้ ≥ 60% — ไม่มีแปลงไหนถึง 90 |
| คุณภาพข้อมูลของขอบเขต | สัดส่วนต้นไม้ ESA WorldCover 2021 | < 60% → "ขอบเขตแปลงมีพื้นที่อื่นปน ผลอาจคลาดเคลื่อน" | 12 จาก 23 แปลง — รวม **ทั้ง 6 แปลงในราชบุรี** |
| ประวัติจากเกษตรกร | แบบฟอร์มภาคสนาม / Phase 2 | "เกษตรกรแจ้งว่าน้ำขังเกือบทุกปี" | ยังไม่มี — **น่าเชื่อถือที่สุด ควรเป็นตัวหลัก** |

**ข้อค้นพบที่ต้องระวัง:**
- แปลงที่ค่าเรดาร์สูงที่สุด (−2 ถึง −3 dB) มีต้นไม้แค่ 2–5% → น่าจะมีบ้าน/ถนนในขอบเขตหรือในวงกลม 100 ม. ของแปลงที่ปักจุดเดียว
  สิ่งปลูกสร้างสะท้อนเรดาร์แรงมาก — เป็นอีกสาเหตุที่ระบบเดิมเตือนผิด (และกระทบทั้งสองวิธี)
- สวนยกร่องในราชบุรีถูก WorldCover จัดว่าเป็นต้นไม้ไม่ถึง 60% (ทรงพุ่มปนร่องน้ำ) — เกณฑ์ 60% อาจต้องปรับสำหรับ plot_type = ยกร่อง ใน 1c
- การเทียบกับสวนรอบข้างได้รับผลจากชนิด/อายุต้นไม้ด้วย (มะพร้าวกับทุเรียนสะท้อนต่างกัน) จึงใช้เป็นข้อมูลประกอบเท่านั้น
- HAND 90 ม. หยาบ บอกได้ระดับพื้นที่ ไม่ใช่ระดับคันดิน/ร่อง

**ยังไม่ได้ทำ (เสนอทีหลัง):** "ระบายน้ำช้าหลังฝน" — นับว่าหลังฝนหนักใช้กี่รอบภาพกว่าค่าเรดาร์กลับสู่ปกติ เทียบสวนรอบข้าง (บอกปัญหาระบายน้ำเรื้อรังได้ตรงกว่า แต่ต้องตรวจจับเหตุการณ์ฝน)

### 8.3 สิ่งที่วิธีใหม่ยังไม่ครอบคลุม
- **แห้งกว่าปกติ** — ตอนนี้จัดระดับเฉพาะฝั่งชื้น (ตัวอย่างจริง: แปลงหนึ่ง z = −2.5 = แห้งกว่าปกติมาก แต่สถานะเป็น "ปกติ")
  เก็บค่า z ไว้ครบแล้ว เสนอเพิ่มสถานะ "แห้งกว่าปกติ" (z ≤ −1 / ≤ −2) สำหรับปัญหา "แห้งเกิน" ใน 1d
