# พยากรณ์ฝน: API กรมอุตุนิยมวิทยา (TMD) และเงื่อนไข Open-Meteo (5 พ.ย. 2569)

ผู้อ่าน: เจ้าของโปรเจกต์ (ใช้ตัดสินใจและเตรียมงบทุน) · ต่อจาก [weather-source-options.md](weather-source-options.md)
· ไม่ใช่คำปรึกษากฎหมาย · **ยังไม่ได้เปลี่ยนโค้ดแหล่งพยากรณ์** (เหตุผลในข้อ 3)

## สรุปสั้น

- **TMD มี API พยากรณ์รายพิกัดจริง และใช้ได้ — ต้องมี token** (สมัครสมาชิกเว็บ แล้วสร้าง Personal Access Token) ฉันสมัครแทนไม่ได้ → **ขั้นตอนสมัครอยู่ข้อ 2**
- **เงื่อนไขการใช้งานของ TMD (ใช้เชิงพาณิชย์/ต้องอ้างที่มาแบบไหน) ฉันยังตรวจไม่ได้** — อยู่หลังหน้าล็อกอิน/หัวข้อ "การยืนยันสิทธิ์การใช้งาน" ในเอกสารทางการ ต้องให้คุณอ่านตอนสมัครแล้วบอกฉัน
- **Open-Meteo ฟรีใช้ไม่ได้กับงานเชิงพาณิชย์** (ข้อ 4) ช่วงทุนวิจัยไม่เก็บเงินใช้ต่อได้ถ้าเป็นงานสาธารณะ/วิจัยจริง แต่เมื่อมีค่าบริการหรือโฆษณาต้องจ่ายแพลนเสียเงิน
- ข้อเสนอ: **ใช้ TMD เป็นแหล่งหลัก + Open-Meteo สำรอง** ตามที่ต้องการ — ทำได้ทันทีที่มี token (ข้อ 3)

## 1. TMD Weather Forecast API — ข้อเท็จจริงที่ตรวจได้

แหล่ง: เอกสารทางการ [data.tmd.go.th/nwpapi/doc](https://data.tmd.go.th/nwpapi/doc/) (อ่านได้เฉพาะหน้าแนะนำ/สารบัญ) และโปรเจกต์ชุมชนที่เรียกใช้จริง
([TMD_weather_HomeAssistant](https://github.com/atomiilol/TMD_weather_HomeAssistant)) — **ส่วนที่มาจากโปรเจกต์ชุมชนยังไม่ยืนยันกับเอกสารทางการ**

| หัวข้อ | ที่ทราบ | ระดับความแน่ใจ |
|---|---|---|
| การเข้าถึง | สมัครสมาชิก → สร้าง "Personal Access Token" ในหน้าเว็บ · ส่งแบบ `Authorization: Bearer <token>` เฉพาะฝั่งเซิร์ฟเวอร์ | สารบัญทางการมีหัวข้อ "การสมัครใช้งาน / การสร้าง OAuth Access Token" · รูปแบบ header มาจากโปรเจกต์ชุมชน |
| ค่าใช้จ่าย | ไม่พบการเก็บเงิน (ไม่ได้ยืนยัน) | ต่ำ |
| โมเดล | Domain 1: ทุก 3 ชม. ถึง **10 วัน** ความละเอียด **9 กม.** · Domain 2: ทุก 1 ชม. ถึง **72 ชม.** ความละเอียด **3 กม.** | สูง (หน้าทางการ) |
| พยากรณ์รายพิกัด | รายชั่วโมง `…/v1/forecast/location/hourly/at` (ถึง 48 ชม.) · รายวัน `…/v1/forecast/location/daily/at` (7 วัน) · พื้นที่ `…/forecast/area/box` | กลาง |
| พิกัดที่รับ | ในประเทศไทยเท่านั้น (ละติจูด ~5.6–20.5, ลองจิจูด ~97.3–105.6) นอกขอบเขตตอบ 422 | กลาง |
| ปริมาณฝน | ฟิลด์ฝนเป็น **มิลลิเมตร** ไม่มี % โอกาสฝน | กลาง — ระบบเตือนของเราใช้ มม. อยู่แล้ว (≥ 35 มม. ใน 3 วัน) |
| ข้อจำกัดการเรียก | 60 ครั้ง/นาที และ 100,000 datapoints/ชม. (datapoint = จุด × ช่วงเวลา × ฟิลด์) | กลาง |
| เงื่อนไข/ใบอนุญาต/การอ้างที่มา | **ไม่ทราบ** | — ต้องอ่านตอนสมัคร |

**ความต้องการของเรา** ใช้ไม่เกิน ~25–100 ครั้ง/วันในช่วงนำร่อง (1 ครั้งต่ออำเภอ/พิกัดกลุ่ม) ห่างจากข้อจำกัดมาก
ขอบเขต 3 วันของเตือนฝนอยู่ในช่วงรายชั่วโมง 48 ชม. + รายวัน 7 วัน

## 2. ขั้นตอนสมัคร TMD ให้คุณทำ (~10 นาที)

1. เปิด https://data.tmd.go.th/nwpapi/register สมัครสมาชิก (ใช้อีเมลโครงการ/มหาวิทยาลัย — ระบุชื่อหน่วยงานตามจริง)
2. ล็อกอินที่ https://data.tmd.go.th/nwpapi/login → เมนู **Personal Access Tokens** → **Create New Token** → คัดลอก token ทันที (แสดงครั้งเดียว)
3. **อ่านเงื่อนไขการใช้งาน/การยืนยันสิทธิ์** ในเอกสาร ([doc](https://data.tmd.go.th/nwpapi/doc/) หัวข้อ "การยืนยันสิทธิ์การใช้งาน") แล้วจดคำตอบ 4 ข้อ:
   (ก) ใช้ในระบบที่เปิดให้เกษตรกร/หน่วยงานรัฐใช้ได้ไหม (ข) ใช้ในโครงการที่มีค่าบริการได้ไหม (ค) ต้องอ้างที่มาด้วยข้อความอะไร (ง) ห้ามแจกจ่ายข้อมูลต่อไหม
4. ใส่ token เป็นตัวแปร `TMD_API_TOKEN` ใน Render Dashboard (ห้ามส่งให้ฉันในแชท — วางที่ `backend/.env` เฉพาะเครื่อง หรือบอกฉันว่าใส่แล้ว)
5. บอกฉัน: "ใส่ TMD token แล้ว" + คำตอบข้อ 3

## 3. ทำไมยังไม่เขียนโค้ดเชื่อม TMD

ฉันไม่มี token จึงเรียกจริงไม่ได้ และ **ยังไม่ทราบรูปแบบ JSON ที่แท้จริง** (ชื่อฟิลด์ฝน หน่วย เวลา) เขียนโดยเดาแล้วเตือนฝนผิดเข้า LINE จริงเสี่ยงเกินไป
เมื่อมี token ฉันจะทำตามนี้ (ประมาณครึ่งวัน รวมทดสอบ):

1. เรียกจริง 1–2 พิกัดราชบุรี ตรวจรูปแบบข้อมูลและเทียบกับ Open-Meteo วันเดียวกัน
2. เพิ่มผู้ให้ข้อมูล `tmd` ใน `weather_alert.get_7day_rain()` — ลำดับ: **TMD → Open-Meteo → (WeatherNext เดิม)** · ถ้า TMD ตอบผิดปกติ/429/หมดเวลา ตกไปใช้ตัวถัดไปเอง
3. ฟิลด์ `source` ใน `WeatherForecast` บอกที่มา · ข้อความเตือนใส่ที่มาตามเงื่อนไขของ TMD (ข้อ 2.3 ค)
4. test รูปแบบข้อมูล + test การตกไปสำรอง · branch → CI → smoke ตามกติกาเดิม
5. เก็บ token ใน env เท่านั้น ไม่ log

## 4. เงื่อนไขไลเซนส์ Open-Meteo (สำหรับงบทุน)

แหล่ง: [Terms](https://open-meteo.com/en/terms) · [Pricing](https://open-meteo.com/en/pricing) · [ประกาศแพลนเชิงพาณิชย์](https://openmeteo.substack.com/p/api-subscriptions-for-commercial)

| หัวข้อ | เงื่อนไข |
|---|---|
| ฟรี (Open-Access) | **เฉพาะไม่ใช่เชิงพาณิชย์** · < 10,000 ครั้ง/วัน, 5,000/ชม., 600/นาที, ~300,000/เดือน · จำกัดต่อ IP ต่อแอป (โฮสต์ร่วมอย่าง Render/Vercel อาจชนเพดานเร็วกว่า) |
| นิยาม "ไม่ใช่เชิงพาณิชย์" | ตามแนว Creative Commons: เว็บ/แอปส่วนตัวหรือไม่แสวงกำไรที่ **ไม่มีค่าสมัครและไม่มีโฆษณา** · งานวิจัยสาธารณะในสถาบันรัฐ · เนื้อหาการศึกษา · บริจาคโดยสมัครใจได้ |
| ถือเป็นเชิงพาณิชย์ | แอป/เว็บที่มีค่าสมัครหรือโฆษณา · ผลิตภัณฑ์/กิจกรรมส่งเสริมการขาย · งานวิจัยที่ไม่เปิดเผยในองค์กรเชิงพาณิชย์ |
| การอ้างที่มา | ข้อมูลอยู่ภายใต้ **CC BY 4.0** — ต้องอ้างที่มา "Weather data by Open-Meteo.com" (ระบบใส่ในข้อความเตือนแล้ว) |
| แพลนเสียเงิน | Standard 1 ล้านครั้ง/เดือน · Professional 5 ล้าน · Enterprise 50 ล้านขึ้นไป · ใช้เชิงพาณิชย์ได้ · เซิร์ฟเวอร์แยก/คีย์ · ราคารายเดือนคงที่ (หน้าราคาไม่แสดงตัวเลข ประกาศเปิดตัวระบุ Standard ~$29/เดือน — ตรวจก่อนใช้) |
| อื่น ๆ | Open-Meteo แก้เงื่อนไขได้ทุกเมื่อ · บล็อก IP ที่ใช้ผิดได้โดยไม่แจ้ง · ให้บริการ "ตามสภาพ" ไม่รับประกัน · กฎหมายสวิตเซอร์แลนด์ · เอกสารไม่ได้พูดถึงการใช้โดยหน่วยงานรัฐโดยตรง |
| ทางเลือก | ติดตั้งเซิร์ฟเวอร์ Open-Meteo เองได้ (ซอฟต์แวร์เปิด) — ไม่แนะนำช่วงนี้ (ต้องดูแลเอง) |

**สถานะของเรา:** ช่วงวิจัยนำร่องที่ไม่เก็บเงินเกษตรกรและไม่มีโฆษณา ใช้ฟรีได้ตามเงื่อนไข · ถ้าโครงการเริ่มเก็บค่าบริการ/ขายให้หน่วยงาน ต้องสมัคร Standard (~$29/เดือน ≈ ฿1,000)
หรือใช้ TMD เป็นแหล่งหลักแล้วใช้ Open-Meteo เป็นสำรองจำนวนน้อย (ซึ่งยังเป็นการใช้เชิงพาณิชย์ — ต้องสมัครแพลนถ้าสำรองทำงานจริงในโครงการที่เก็บเงิน)

## 5. ข้อเสนอ

| ช่วง | แหล่งหลัก | สำรอง | ค่าใช้จ่าย |
|---|---|---|---|
| วิจัยนำร่อง (ทุน) | TMD (เมื่อได้ token และเงื่อนไขอนุญาต) | Open-Meteo ฟรี | ~฿0 |
| ให้บริการประจำ/เก็บเงิน | TMD | Open-Meteo Standard | ~฿1,000/เดือน (ตรวจราคาจริง) |

ถ้าเงื่อนไขของ TMD ห้ามใช้ในโครงการนี้ → คง Open-Meteo เป็นหลัก (ฟรีช่วงวิจัย, Standard ช่วงให้บริการ)
