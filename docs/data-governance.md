## 2. วัตถุประสงค์และฐานทางกฎหมาย (พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562)

| วัตถุประสงค์ | ฐาน |
|---|---|
| วิเคราะห์แปลงและแสดงคำแนะนำให้เจ้าของ | จำเป็นต่อการให้บริการตามที่ผู้ใช้ขอ (มาตรา 24(3)) |
| แบ่งปันแปลงกับเจ้าหน้าที่เกษตรในอำเภอ | **ความยินยอม** (เลือกเข้า ค่าเริ่มต้นปิด ถอนได้ทุกเมื่อ) |
| ใช้รูป/การยืนยันภาคสนามปรับปรุงระบบและสอนระบบจำแนกพืช | **ความยินยอม** (เลือกเข้า ค่าเริ่มต้นปิด) — ชุดฝึกโมเดลจำแนกพืชใช้เฉพาะแปลงของผู้ที่เลือกข้อนี้ |
| ทายชนิดพืชของแปลงให้เจ้าของ | จำเป็นต่อการให้บริการ — ผลทายไม่เปลี่ยนข้อมูลแปลงจนกว่าผู้ใช้ยืนยัน |
| แปลงอ้างอิงจากหน่วยงาน (ทะเบียนเกษตรกร) | ตามข้อตกลงกับหน่วยงานเจ้าของข้อมูล (DPA) — ยังไม่มี ห้ามนำเข้าก่อนมีข้อตกลง |
| จุดสำรวจพืชของเจ้าหน้าที่ | ความยินยอมของเจ้าของแปลง (เจ้าหน้าที่ถามและยืนยันในแอปทุกจุด) — ใช้สอนระบบเท่านั้น ไม่แสดงในแอป |
| สถิติรวมสำหรับหน่วยงานรัฐ | ประโยชน์โดยชอบด้วยกฎหมาย — ส่งออกเป็นตัวเลขรวมรายอำเภอเท่านั้น |
| บันทึกการเข้าถึง / ความปลอดภัย | ประโยชน์โดยชอบด้วยกฎหมาย และหน้าที่ตามมาตรา 37 |

แอปถามความยินยอมทุกคน (รวมผู้ใช้เดิม) ก่อนใช้งานต่อ · server ไม่ให้สร้าง/วิเคราะห์แปลงถ้ายังไม่ยอมรับนโยบายฉบับปัจจุบัน
· เปลี่ยนเนื้อหาที่มีผลต่อสิทธิ์ → เปลี่ยนฉบับ (`backend/privacy.py`) แล้วระบบถามใหม่ทุกคน

## 3. ใครเข้าถึงอะไร (ตรวจที่ server ทุกคำขอ)

| บทบาท | เห็น | แก้ | ได้บทบาทอย่างไร |
|---|---|---|---|
| เกษตรกร | แปลงตัวเอง | แปลงตัวเอง ลบ/รวมประวัติ | ค่าเริ่มต้น |
| เจ้าหน้าที่ | แปลงที่ตัวเองวาด + แปลงในอำเภอที่รับผิดชอบ **เฉพาะเจ้าของที่ยินยอมแบ่งปัน** | พืช/ประเภทสวน/ขอบเขต ตรวจซ้ำ แนบรูป ยืนยันภาคสนาม (ลบ/รวมประวัติไม่ได้) | รหัสเชิญจากผู้ดูแล (หมดอายุ จำกัดจำนวนคน) |
| ผู้ดูแลระบบ | ทุกแปลง ตารางคำแนะนำ ผู้ใช้ สถิติ | บทบาท รหัสเชิญ คำแนะนำ ลบข้อมูลถาวรเมื่อผู้ใช้ขอ | รหัสเชิญแบบผู้ดูแล / หน้า admin (`ADMIN_API_KEY`) |
| หน่วยงานรัฐ | ไฟล์ตัวเลขรวมรายอำเภอ (ไม่มีชื่อ/พิกัด) | — | ผู้ดูแลส่งให้ |

- ทุกการเข้าดู/แก้แปลงของคนอื่นถูกบันทึกใน `audit_logs` · เจ้าของแปลงดูได้ที่ "ข้อมูลของฉัน → ใครเปิดดูแปลงของฉัน"
- ไม่มีสิทธิ์ = ตอบ "ไม่พบแปลงนี้" (ไม่บอกใบ้ว่ามีแปลงนั้นอยู่)
- รายการแปลงของเจ้าหน้าที่ไม่ส่ง LINE userId ของเกษตรกร · หน้า admin แสดง userId แค่ 4 ตัวท้าย

## 4. การส่งข้อมูลให้หน่วยงานรัฐ (B2G)

- ส่งเฉพาะตัวเลขรวมรายอำเภอ: จำนวนเกษตรกร แปลง พื้นที่ ชนิดพืช ประเภทสวน สถานะความชื้นเทียบปกติ
- **อำเภอที่มีเกษตรกร 1–2 คน ซ่อนตัวเลขทุกช่องเป็น "<3"** (กันระบุตัวบุคคลจากตัวเลขเล็ก) — ไฟล์ "ส่งหน่วยงาน" ในหน้าภาพรวมจังหวัด
- แผนที่จังหวัดวางวงกลมที่จุดกลางอำเภอ ไม่ใช่ตำแหน่งแปลงจริง
- ผลยืนยันภาคสนาม (มีพิกัดจุด) ส่งออกได้เฉพาะผู้ดูแล ใช้วัดผลและสอนระบบ — ถ้าจะให้หน่วยงานใช้ ต้องตกลงขอบเขตการใช้และเป็นแปลงของผู้ที่ยินยอมข้อ "ใช้ปรับปรุงระบบ"
- ตัวเลขความแม่นยำรายงานพร้อมขนาดตัวอย่างเสมอ ("ตรง x ใน n ครั้ง") ไม่แสดงเปอร์เซ็นต์ถ้า n < 10

## 7. ความปลอดภัย

- ยืนยันตัวตนด้วย LINE ID token ตรวจที่ server · ห้ามเชื่อ userId จากแอป
- ฐานข้อมูลเปิด RLS ทุกตาราง (เข้าได้เฉพาะ backend) · ถอนสิทธิ์ role anon/authenticated ทั้งหมด
- รูปและรายงานอยู่ใน bucket private เปิดด้วย signed URL อายุสั้น · ไฟล์รูปไม่มี EXIF
- จำกัดจำนวนคำขอต่อผู้ใช้/IP · รหัสเชิญเดาไม่ได้ จำกัดการลอง
- secret อยู่ใน env เท่านั้น (repo เป็น public) · backup ฐานข้อมูลก่อน migration ทุกครั้ง

## 8. สิทธิ์ของเจ้าของข้อมูล (ทำได้เองในแอป)

ดูและดาวน์โหลดข้อมูลของตัวเอง (JSON) · ดูว่าใครเปิดดูแปลง · เปลี่ยน/ถอนความยินยอม · ขอลบข้อมูล · แก้ไขแปลง
· ร้องเรียน สคส. — ช่องทางติดต่อผู้ควบคุมข้อมูล: ปุ่ม "ติดต่อเจ้าหน้าที่" ในแชท LINE

## 10. เรื่องที่ยังต้องตัดสินใจ

1. ชื่อนิติบุคคล/หน่วยงานที่เป็นผู้ควบคุมข้อมูล และช่องทางติดต่อทางการ (ตอนนี้ระบุ "ทีมพัฒนา IAM ROOT")
2. ข้อตกลงการประมวลผลข้อมูล (DPA) กับสำนักงานเกษตรจังหวัด ถ้าเจ้าหน้าที่ของรัฐเข้าใช้ข้อมูลเกษตรกร
3. ระยะเวลาเก็บ `audit_logs` และ `events` (ตอนนี้ไม่มีกำหนดลบ)
4. การโอนแปลงที่เจ้าหน้าที่วาดแทนให้เกษตรกรเมื่อเขาเข้าระบบ
5. ขอบเขตตำบล (ตอนนี้เจ้าหน้าที่รับผิดชอบระดับอำเภอ เพราะยังไม่มีขอบเขตตำบลในระบบ)
